## Context

cc-hub is a CLI tool with no web server, no database schema migrations, and no UI. Testing focuses on:
1. Pure function logic (model resolution, formatting, path utilities)
2. Service adapters (mocked external APIs)
3. No E2E or visual tests (CLI — no browser)

## Unit Testing

**Framework:** `bun:test` (built-in)

**What to test:**
- All pure functions in `src/infra/` (paths, spinner, stdin, prompt)
- Model resolution functions in `src/services/models.ts`
- Formatting functions in `src/services/format.ts`
- Command argument parsing (Commander.js option handling)

**What NOT to unit test:**
- Real Keychain access (mock `creds.ts` exports)
- Real DB writes (use temp SQLite or mock `getDb()`)
- Real Telegram API calls (mock `telegram.ts`)
- Real OpenRouter/Poyo/Soniox calls (mock HTTP)

**File convention:**
- `*.test.ts` next to source: `src/infra/spinner.ts` → `src/infra/spinner.test.ts`
- OR in `tests/` mirroring src: `src/services/models.ts` → `tests/services/models.test.ts`
- Test names describe behavior: `"findModel: returns model by canonical ID"`

**Example:**

```typescript
import { describe, it, expect } from 'bun:test';
import { findModel } from '../../src/services/models.ts';

describe('findModel', () => {
  it('returns model by canonical ID', () => {
    const model = findModel('anthropic/claude-sonnet-4.6');
    expect(model).toBeDefined();
    expect(model?.id).toBe('anthropic/claude-sonnet-4.6');
  });

  it('returns undefined for unknown model', () => {
    const model = findModel('unknown/model');
    expect(model).toBeUndefined();
  });
});
```

## Integration Testing

**Framework:** `bun:test` with real in-memory/temp SQLite

**What to test:**
- `getDb()` creates schema correctly
- `log add` writes an event row
- `digest preview` reads events correctly
- `purge` removes events older than N days

**Setup:**
- Use a temp DB path per test (e.g., `:memory:` or `tmp/test-TIMESTAMP.db`)
- Override `DB_PATH` in `src/infra/paths.ts` or inject DB client via parameter
- No global state — each test gets a fresh DB

N/A — cc-hub is a pure CLI tool with no UI screens.

## No E2E by Default

CLI E2E (spawning `cc-hub` as a subprocess and asserting stdout) is possible with `Bun.spawn()` but not required. Unit + integration tests cover all critical paths. Add subprocess tests only for critical regression scenarios.
